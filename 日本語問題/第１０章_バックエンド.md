# ハッカソン特化型 Go言語ブートキャンプ

## 第10章：バックエンドの完成形！〜REST APIを構築しよう〜

第8章で「Webサーバー」の立ち上げ方を学び、第9章で「JSON」の扱い方を学びました。今回はこの2つを合体させて、ハッカソンでのバックエンド開発における最大の目標である**「REST API（レスト・エーピーアイ）」**を完成させましょう！

例えば「コンビニのトイレマップアプリ」を作る場合、フロントエンド（スマホ画面）から「現在地の緯度・経度」をサーバーに送信し、サーバー側で近くの店舗を検索して「店舗情報とトイレの有無」をJSON形式でスマホに返却する、という一連の通信が必要になります。今回はまさにその中核となるコードを記述します。

---

### 10.1 GETとPOSTの違いを理解する

Webの通信（HTTP）には、目的によっていくつかの「メソッド（通信の種類）」が使い分けられます。ハッカソンで絶対に使うのが以下の2つです。

* **GET（ゲット）**: データを「取得」するためのメソッド。ブラウザでURLを入力して画面を開くのは、すべてこのGET通信です。
* **POST（ポスト）**: データを「送信・作成」するためのメソッド。パスワードを送信したり、アプリから現在地などのJSONデータをサーバーに送ったりする際に使います。

今回は、フロントエンドからJSONデータを受け取り、処理結果をJSONで返す「POSTメソッド専用のAPI」を作ります。

---

### 10.2 APIサーバーの実装

ターミナルを開き、`nvim main.go` でNeovimを起動して、以下のコードを記述しましょう。

~~~go
package main

import (
    "encoding/json"
    "fmt"
    "net/http"
)

// ① フロントエンドから送られてくるJSONの設計図
type RequestData struct {
    Latitude  float64 `json:"latitude"`  // 緯度
    Longitude float64 `json:"longitude"` // 経度
}

// ② バックエンドから返却するJSONの設計図
type ResponseData struct {
    StoreName string `json:"store_name"` // 店舗名
    HasToilet bool   `json:"has_toilet"` // トイレの有無
}

// APIのメイン処理（ハンドラ）
func apiHandler(w http.ResponseWriter, r *http.Request) {
    // 1. POST通信以外はエラーにして弾く
    if r.Method != http.MethodPost {
        http.Error(w, "POSTメソッドのみ許可されています", http.StatusMethodNotAllowed)
        return
    }

    // 2. フロントエンドから送られてきたJSONを読み取る
    var req RequestData
    // RequestのBody（中身）から直接JSONを読み込み、reqに変換（デコード）する
    err := json.NewDecoder(r.Body).Decode(&req)
    if err != nil {
        http.Error(w, "JSONの読み込みに失敗しました", http.StatusBadRequest)
        return
    }

    // ターミナルに受信したデータを表示して確認
    fmt.Printf("受信した座標: 緯度 %f, 経度 %f\n", req.Latitude, req.Longitude)

    // 3. （ここでデータベース検索などの複雑な処理を行うと仮定します）
    // 今回はダミーのデータを作成して返却します
    res := ResponseData{
        StoreName: "ハッカソンマート 渋谷店",
        HasToilet: true,
    }

    // 4. フロントエンドへJSONを返却する準備
    // 「今から返すデータはJSON形式ですよ」とブラウザやアプリに教えてあげるヘッダー設定
    w.Header().Set("Content-Type", "application/json")

    // 5. 構造体(res)をJSONに変換（エンコード）して、直接ResponseWriter(w)に書き込む
    json.NewEncoder(w).Encode(res)
}

func main() {
    // "/api/toilet" というURLパスに、apiHandler関数を紐付ける
    http.HandleFunc("/api/toilet", apiHandler)

    fmt.Println("APIサーバー起動: http://localhost:8080/api/toilet で待機中...")
    http.ListenAndServe(":8080", nil)
}
~~~

コードが書けたら `Esc` を押し、`:wq` で保存してNeovimを終了します。

### 10.3 プログラムの丁寧な解説

今回のコードには、実戦でそのまま使える非常に重要なテクニックが詰まっています。

* **`r.Method`**
  ユーザーがどのような方法（GETなのかPOSTなのか）でアクセスしてきたかを確認できます。`http.MethodPost` は `"POST"` という文字列を表すGo言語の便利な定数です。

* **`json.NewDecoder(r.Body).Decode(&req)`**
  第9章では `json.Unmarshal` を使いましたが、Webサーバーのように「通信のデータの流れ（ストリーム）」から直接JSONを読み取る場合は、この `NewDecoder` を使うのがGo言語のベストプラクティスです。メモリを節約し、高速に処理できます。

* **`w.Header().Set("Content-Type", "application/json")`**
  HTTP通信において、データ本体を送る前に「設定情報（ヘッダー）」を送るルールがあります。ここで「返却するデータはただの文字ではなく、JSONですよ」と明示することで、スマホアプリ側がデータを正しく処理できるようになります。

* **`json.NewEncoder(w).Encode(res)`**
  これも `json.Marshal` の進化版です。構造体をJSONに変換しつつ、そのまま `w`（ブラウザへの返信箱）に一気に書き込んでくれます。コードがとても短くスッキリします。

**【動作確認について】**
このプログラムは「POST通信」を待っているため、ブラウザのURL欄に入力（GET通信）しても「POSTメソッドのみ許可されています」というエラーになります。ハッカソンでは、フロントエンド担当者が作成したアプリから通信してもらうか、「Postman」や「cURL（カール）」といったAPIテストツールを使って動作確認を行います。

### 10.4 第10章の確認問題

**問題1**
クライアント（スマホアプリなど）からサーバーへ、新しいデータを送信したり作成したりする際によく使われるHTTPメソッドはどれですか？
A) `GET`
B) `POST`
C) `DELETE`

**問題2**
HTTPリクエストを受け取った際、その通信がどのメソッド（GETやPOSTなど）で行われたかを確認するためのフィールド（変数）はどれですか？
A) `r.Header`
B) `r.Method`
C) `r.Body`

**問題3**
Webサーバーに送られてきたリクエストの中身（ストリーム）から直接JSONデータを読み取り、Goの構造体に割り当てるために使用する関数・メソッドの組み合わせはどれですか？
A) `json.Unmarshal`
B) `json.NewDecoder(r.Body).Decode()`
C) `json.ReadJSON`

**問題4**
サーバーからJSON形式のデータを返却する際、レスポンスに「これはJSONデータである」と明示するために `w.Header().Set()` で指定する項目と値の正しい組み合わせはどれですか？
A) `Content-Type`, `text/html`
B) `Content-Type`, `application/json`
C) `Data-Type`, `json/format`

**問題5**
Goの構造体をJSONデータに変換し、そのまま `http.ResponseWriter`（レスポンスの書き込み先）へ直接出力するために使用する関数・メソッドの組み合わせはどれですか？
A) `json.Marshal`
B) `json.Send(w)`
C) `json.NewEncoder(w).Encode()`

---

### 10.5 解答と解説

**問題1の正解：B**
*解説：*
* **A) `GET`**：データを取得する際に使用します。
* **B) `POST`**：データを送信・作成する際に使用します。API開発におけるデータ受け取りの主役です。
* **C) `DELETE`**：データを削除する際に使用するメソッドです（REST APIの設計規則でよく使われます）。

**問題2の正解：B**
*解説：*
* **A) `r.Header`**：通信の設定情報（ブラウザの種類や認証トークンなど）が入っています。
* **B) `r.Method`**：アクセスに使用されたHTTPメソッド（"GET"や"POST"など）が文字列で格納されています。
* **C) `r.Body`**：送られてきたデータそのもの（JSON文字列やアップロードされた画像データなど）が入っています。

**問題3の正解：B**
*解説：*
* 第9章で学んだ `json.Unmarshal` は、すでに変数に入っている文字列（`[]byte`）を変換する時に使います。一方、`json.NewDecoder` はネットワーク通信のような「少しずつ流れてくるデータ」から直接効率よく読み取るためのもので、Webサーバー開発ではこちらが推奨されます。

**問題4の正解：B**
*解説：*
* `Content-Type` は通信データの種類を示す国際的な標準ルールです。JSONを返す場合は必ず `application/json` に設定します。（文字だけの時は `text/plain`、Webページの時は `text/html` となります）。

**問題5の正解：C**
*解説：*
* デコード時と同じ理由で、変換した結果を変数に一度保存する `json.Marshal` よりも、変換しながら直接ネットワークに流し込む `json.NewEncoder(w).Encode()` の方が、Webサーバーの処理として効率的でコードも短くなります。
